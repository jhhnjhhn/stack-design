# AI coding compatibility

Assess documentation quality (20), public examples (15), type safety (15), API stability (15), error clarity (10), ecosystem maturity (10), breaking-change frequency (10), and tooling (5). Report High, Medium, or Low with evidence.

Prefer boring, documented, version-stable patterns. Distinguish technology from version and mention a version only when it changes the decision. Lower confidence for recently changed APIs, sparse examples, implicit runtime behavior, fragmented tooling, or weak diagnostics.
